A storytelling engine

An idea goes in.
A story goes out.

Storyseam is convention over configuration. One command scaffolds a story folder; every later command finds what it needs by looking in known places. There is no database, no server, no app. The filesystem is the state.

npx storyseam init my-film

Requires node 18.17+, ffmpeg, and a backend.

Fig. 01 The pipeline

  1. /start-storyscaffold
  2. /write-scriptscript
  3. /shotlist30s blocks
  4. /castassets
  5. /renderclips
  6. /assembleconcat
  7. film.mp4done

Each command is a thin wrapper that loads one skill. Blocks render sequentially and the last frame of block N becomes the first reference of block N+1 — the chain is the continuity.

Nothing downstream needs configuring, because everything knows where to look. /cast finds character sheets in assets/images/characters/ without being told.

The tree is also the program counter. A script but no shot list means /shotlist is next. Clips but no final/ means /assemble. /render resumes from state.json and never re-renders a block already on disk.

Absence is meaningful: script.md is deliberately not seeded, because its absence is how the engine knows the script is unwritten.

Fig. 05 The registry

Knowing how to prompt one model is craft that changes when the model does, so it does not live in the pipeline. Each model has one default director and any number of alternates, asked for by name. A registry ships bundled with the package — init works offline and is pinned to the release; update pulls newer ones.

Every item is hash-checked against the catalogue and may only write under the skills directory. Storyseam never handles an API key's value — it reports whether the variable is set, and its length, and nothing else.

Fig. 06 Load-bearing constraints

Five invariants, not defaults. They are written in exactly one file and generated into every copy; a build check fails if a copy drifts or any skill contradicts one.

  1. Never generate music. Every video prompt ends with the canonical audio line. A render that comes back with music is a failed render. The human scores it afterwards, in the one folder Storyseam never writes to.
  2. Video is rendered at 480p. A story may not raise the resolution, whichever model renders it, because resolution is the cost lever.
  3. Images are GPT Image 2 at 2k. A soft reference poisons every block that cites it.
  4. The backend is configuration. One provider named per capability, verified before anything is spent, never swapped silently.
  5. One block at a time, chained. Never fan out video generation in parallel; the chain is the continuity.
